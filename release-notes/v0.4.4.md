## Highlights

Switching no longer moves your cursor. Workspace switches now change the Space
on the display with the focused window without touching the cursor, and display
switches leave it where it is unless you ask otherwise. Two new switches in
**Settings › General** control this:

- **Switch workspaces on the focused display** (on by default). Turn it off to
  change the Space on the display under the cursor instead.
- **Move cursor to the target display** (on by default). Turn it off to keep the
  cursor in place when switching displays.

Display switching is also noticeably faster, and pressing a display hotkey
several times in quick succession now walks across displays as expected.

## Improvements

- Switching to a display with windows focuses its frontmost window directly
  through the window server instead of waiting on app activation.
- Switching to a display with no windows activates it by clicking an empty
  spot on its menu bar, chosen by inspecting that display's own menu bar.
  The cursor is back where it was within a few milliseconds.
- Hotkey actions no longer run inside the input event tap, so they cannot
  stall input while they work.
- `settings.json` gains `workspaceTargetsFocusedDisplay` and
  `moveCursorToTargetDisplay` (both default `true`).

## Fixes

- Switching to an empty display could open a menu or activate a menu bar
  item on that display.
- The Settings window followed you back to the Space it was last closed on;
  it now opens on the current Space and has a proper menu bar while open.
